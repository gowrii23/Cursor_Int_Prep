LLM inference systems · study note (added 2 Nov 2026)

Speculative decoding: guess fast, check in bulk

A small draft model guesses the next few tokens; the big model checks all of them in one forward pass. Result: 2–3× faster generation with output identical to the big model alone.

🧠 Intern drafts, Boss signs. The intern writes fast; the boss reads the whole page in one go, signs up to the first mistake, fixes that word and hands it back.

1 · The walkthrough

  1. Problem. A big LLM makes one token per forward pass, and each pass is slow because all the weights are loaded from GPU memory.
  2. Draft. A small model (say 1B) guesses k = 4 tokens: the cat sat on.
  3. Verify. The big model (say 70B) runs one pass over all 4 guesses and gets its own prediction at every position.
  4. Accept / reject. It agrees with the cat sat but would have said under, not on. Keep 3, drop on, add under as a free bonus token.
  5. Result. 4 tokens for one big-model pass instead of 4 passes.

2 · "But the big model still runs, so why is verify free?"

Generating is sequential, checking is parallel. To produce token 2 you need token 1 first, so generation is pass → token → pass → token. The draft tokens already exist, so the big model takes the whole sequence in one batch. The causal mask lets each position see only earlier tokens, so one pass gives the model's prediction at every position: the same trick as teacher forcing in training and prefill of a prompt.

One pass over 5 tokens ≈ one pass over 1 token, because small-batch inference is memory-bound: the time goes to loading weights, not maths.

Weights are loaded once and reused for all positions, so extra tokens cost well under a millisecond. "Free" stops being true at large batch sizes, where the GPU becomes compute-bound. That's why speculative decoding helps most at low batch / single-user latency.
🧠 Write one by one, read all at once. The big model only ever reads the draft.

3 · How many tokens per big pass?

Let α = the chance the big model accepts a draft token and k = draft length. You keep accepted tokens until the first rejection, plus one bonus token from the big model. The expected tokens per big pass is a geometric sum:

E[tokens] = 1 + α + α² + … + α^k = (1 − α^(k+1)) / (1 − α)
αkWorkingTokens / big pass
0.84(1 − 0.8⁵) / 0.2 = (1 − 0.328) / 0.2≈ 3.36
0.54(1 − 0.5⁵) / 0.5 = (1 − 0.031) / 0.5≈ 1.94
0.98(1 − 0.9⁹) / 0.1 = (1 − 0.387) / 0.1≈ 6.13

Real speedup also pays for the drafts. If one draft step costs c of a big pass, a round costs 1 + k·c, so speedup ≈ E[tokens] / (1 + k·c). With α = 0.8, k = 4, c = 0.05: 3.36 / 1.2 ≈ 2.8×.

Lossless: accept/reject uses rejection sampling (accept with probability min(1, p_big / p_draft); on rejection, resample from the leftover distribution), so the output follows the big model's distribution exactly.

5 · Where you'll see it

  • Serving engines (vLLM, TensorRT-LLM) support draft-model speculation.
  • MTP / Medusa / EAGLE: instead of a separate draft model, extra heads on the big model draft tokens. See the MTP row in Colibri.
  • SLM angle: a small, well-matched model is exactly what makes a good draft model.

6 · Self-check

  • Explain why verifying k tokens costs about one pass (memory-bound + causal mask).
  • Derive (1 − α^(k+1)) / (1 − α) from "accept until first miss, plus a bonus".
  • Compute tokens/pass for α = 0.7, k = 3. (Answer: (1 − 0.7⁴)/0.3 ≈ 2.53)
  • Say when it stops helping: large batches (compute-bound) or low α.
  • Explain why the output is identical to the big model (rejection sampling).
